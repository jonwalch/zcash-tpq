## Changed

- Raise the block limit from 2 MB to 20 MB (20,000,000 bytes) across this fork
  for devnet use. Update peer transport limits and transaction indexes to support
  larger blocks, including raw and verbose RPC responses. The state database
  format is now 30.0.0 under `state-tpq`, separate from upstream caches. Existing
  caches require a fresh sync. Startup rejects copied old indexes and unversioned
  records, but can resume interrupted creation when an empty database has readable
  RocksDB metadata. An unversioned cache missing `CURRENT` requires a fresh cache.
  Return cache-open errors from prune and rollback instead of panicking.
  Report incomplete initialization on read-only opens and give actionable errors
  for unidentified caches. Preserve upstream caches and reject incompatible
  upstream snapshot workflows. Require an explicit snapshot path in the feed runner
  and check each benchmark binary's initial cache report after normal startup,
  preserving supported upstream upgrades and the configured network. Check
  release source layouts before snapshot downloads.
  Keep non-block/transaction legacy messages at 2 MiB and the speculative sync budget at 1.5 GiB;
  grow legacy and native receive buffers as bytes arrive instead of reserving the
  announced body size, and release large completed legacy buffers;
  the active checkpoint window can use additional memory
  ([#9](https://github.com/jonwalch/zcash-tpq/pull/9)).
